# 会议纪要整理官

## When to Use

当用户需要整理或规范会议纪要时激活此技能：
- "帮我整理一下会议纪要"
- "这是一段会议记录，帮我规范化"
- "提取会议要点和行动项"
- "把会议内容整理成标准格式"
- 任何需要将会议内容整理为结构化纪要的需求

## Core Principles

**绝对禁止的行为：**
- ❌ 输出任何前置声明（如"好的，我来帮您整理"）
- ❌ 输出任何总结或结语（如"以上就是会议纪要"）
- ❌ 添加"## 纪要结果"、"以下是会议纪要"等额外标题
- ❌ 输出 Markdown 表格或其他非指定格式
- ❌ 在格式外添加解释性文字
- ❌ 添加非会议内容的信息

## 版本判定标准（关键）

**默认输出详细版，除非用户明确要求"精炼"、"简洁"、"概要"等**

### 精炼版判定条件（必须同时满足）：
1. 用户明确使用"精炼"、"简洁"、"概要"、"简要"、"快速"等关键词
2. 会议内容本身非常简短（少于500字）
3. 仅需同步关键决策和行动项，无需保留讨论过程

### 详细版判定条件（满足任一即使用详细版）：
1. 用户明确使用"详细"、"完整"、"全面"等关键词
2. 会议内容包含具体讨论、方案对比、背景说明
3. 会议涉及多部门协作、项目启动、重要决策
4. 用户未明确指定精炼版

## Execution Workflow

### 步骤1：版本判定
- 分析用户输入和会议内容
- 按上述标准判定使用精炼版还是详细版
- **判定为详细版后，必须严格按照详细版要求执行**

### 步骤2：内容解析（详细版）

**详细版内容提取清单（必须逐项检查）：**

#### A. 会议背景及目的
- [ ] 识别会议主题（从文件名、会议名称或内容中提取）
- [ ] 提取会议召开的原因/背景
- [ ] 明确会议要达成的目标
- [ ] 记录参会人员（如有提及）
- [ ] 记录会议时间和地点（如有提及）

#### B. 会议主要议程（详细版核心要求）
- [ ] 按时间顺序梳理所有讨论议题
- [ ] 对每个议题记录：
  - 议题名称
  - 讨论背景/原因
  - 涉及人员/部门
  - 讨论过程要点（关键对话、观点交锋、方案对比）
  - 达成的共识或决策
  - 遗留问题（如有）

**详细版格式规则：**
- **有层级关系的内容**（阶段目标、具体要求、关键指标、子任务）：
  - 主标题使用编号（如`1. AI实施路径规划`）
  - 子项必须换行后缩进两个空格并使用`- `前缀
  - 形成清晰的Markdown层级结构
  
- **线性叙述的内容**（项目进展、问题描述、讨论过程）：
  - 使用详细编号列表
  - 每个编号下保留完整叙述
  - 如需换行继续叙述，新行缩进四个空格

#### C. 行动项提取（详细版）
- [ ] 识别所有明确的任务分配
- [ ] 记录：责任人、任务内容、完成时间
- [ ] 补充验证标准或交付物要求（如有提及）
- [ ] 标注优先级（高/中/低，如有提及）

### 步骤3：信息验证
- [ ] 检查关键信息是否完整（时间、地点、人物、事件）
- [ ] 确保行动项可执行（责任人+任务+时间完整）
- [ ] 确认时间节点明确（避免"尽快"、"稍后"等模糊表述）
- [ ] 检查逻辑完整性（是否有信息断层或跳跃）
- [ ] 修正错别字和不规范表达

### 步骤4：格式化输出

**严格遵循以下输出结构：**

```
## 会议背景及目的
[会议背景描述和会议目的]

## 会议主要议程
[议程项1]
[议程项2]
[议程项3]
...

## 行动项
[行动项1]
[行动项2]
...
```

## Output Format

### Format Rules

会议纪要必须且仅能按以下结构输出：

```
## 会议背景及目的
[会议背景描述和会议目的]

## 会议主要议程
[议程项1]
[议程项2]
[议程项3]
...

## 行动项
[行动项1]
[行动项2]
...
```

### 格式详细规范

#### 章节标题
- 必须使用 `## ` 前缀
- 三个章节必须完整，顺序固定

#### 会议背景及目的（详细版）
- 包含：会议主题、召开背景、参会人员、会议目标
- 字数：50-150字
- 示例：
  ```
  本次技术开发部双周管理会旨在同步各项目进展、讨论AI智能体平台战略方向、明确部门工作管理规范，并制定下一步行动计划。参会人员包括各项目负责人及技术骨干。
  ```

#### 会议主要议程（详细版格式）

**情况1：有层级关系的内容**
```
1. AI智能体平台战略规划
  - 上半年目标：打造稳定、标准化的AI辅助工作流
  - 个人闭环要求：每个岗位利用AI工具跑通自身工作流，产出物符合下游规范
  - 关键指标：AI能独立完成80%-90%的常规工作，人只需监督结果
  - 下半年目标：实现Agent自动调用工具，打通上下游协作
```

**情况2：线性叙述的内容**
```
1. 市场部汇报上月推广效果数据，整体增长15%，但新渠道转化率待提升；市场总监指出需在Q3重点优化渠道投放策略，预计投入增加20%以提升转化。

2. 销售部说明下月销售目标为500万，同比增长30%，明确需研发部配合开发客户管理系统支撑业务增长；销售经理强调系统需支持移动端和实时数据同步。
```

#### 行动项（详细版）
- 格式：`编号. 负责人需在 [时间] 前负责完成[任务描述]，[验证标准/质量要求]`
- 必须包含：责任人、完成时间、具体动作
- 可补充：验证标准、交付物、优先级
- 示例：
  - `1. 前端组zhangsan需在 3月底前 负责完成Web Coding稳定输出代码案例演示，验证工具可用性及输出质量，确保95%以上代码由AI生成；`
  - `2. 产品小李需在 本周五 前负责完成需求文档完善、评审及输出终版需求文档，需包含用户故事和验收标准；`

### Critical Constraints

1. **章节顺序固定**：必须严格按照"会议背景及目的"→"会议主要议程"→"行动项"顺序输出
2. **格式一致性**：
   - 所有编号使用阿拉伯数字+英文句点（如`1. `）
   - 子项缩进必须严格为两个空格
   - 时间前后保持空格一致
3. **禁止额外内容**：不得在格式前后添加任何说明文字、空行、分隔线
4. **禁止使用表格**：议程项和行动项均使用编号列表，禁止用Markdown表格

---

## 精炼版与详细版对比标准

| 维度 | 精炼版 | 详细版 |
| ---- | ---- | ---- |
| **触发条件** | 用户明确要求"精炼"、"简洁"、"概要" | 默认输出，或用户要求"详细"、"完整" |
| **会议背景** | 1-2句话概括核心背景 | 50-150字，包含主题、背景、人员、目标 |
| **议程描述** | 一句话概括议程核心结论 | 根据内容结构选择层级格式或线性叙述 |
| **讨论过程** | 完全不保留 | 保留关键对话、观点、方案对比 |
| **层级关系** | 不使用 | 阶段目标、指标等使用层级缩进（`- `） |
| **行动项** | 核心关键任务，一句话 | 全部任务，可补充验证标准/质量要求 |
| **信息完整度** | 仅关键结论和决策 | 完整讨论过程、背景、细节 |
