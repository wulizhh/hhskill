## 基础设计规范

### 尼尔森十大可用性原则

1. **状态可见** - 操作即时反馈，响应时间小于用户等待时间
2. **环境贴切** - 使用用户熟悉的语言和概念
3. **撤销重做** - 允许用户撤销操作
4. **一致性** - 同一用语、功能、操作保持一致
5. **防错原则** - 预防错误比提示更好
6. **易取原则** - 减少用户记忆负担
7. **灵活高效** - 为中级用户设计，兼顾初级和高级用户
8. **易扫原则** - 突出重点，弱化无关信息
9. **容错原则** - 帮助用户从错误中恢复
10. **人性化帮助** - 无需提示 → 一次性提示 → 常驻提示 → 帮助文档

## 布局规范

### 页面尺寸

| 平台 | 推荐尺寸 | 说明 |
|------|----------|------|
| 移动端 | 375×812 | iPhone X 标准尺寸 |
| PC端 | 1440×900 | 主流桌面显示器 |

### 栅格系统

- **12等分栅格** - 适用于大多数Web页面
- **24等分栅格** - 适用于复杂数据展示页面

### PC端布局方式

1. **上下布局** - 导航在上，内容在下
2. **"T"型布局** - 顶部导航 + 左侧菜单
3. **上中下布局** - 顶部导航 + 中间内容 + 底部信息
4. **综合布局** - 混合多种布局方式

### 间距规范

合理的间距能让界面更加整洁、主次分明。根据场景定义不同层级的间距：

- **大间距** - 模块之间（32px-48px）
- **中间距** - 卡片之间（16px-24px）
- **小间距** - 元素之间（8px-12px）
- **微间距** - 文字与图标（4px）

## 颜色规范

### 颜色体系

| 类型 | 用途 | 选择建议 |
|------|------|----------|
| **主色** | 品牌识别、主要操作 | 使用品牌色，饱和度适中 |
| **辅助色** | 次要操作、信息提示 | 与主色协调，形成对比 |
| **中性色** | 背景、文字、边框 | 灰度色板，层次清晰 |
| **功能色** | 成功、警告、错误、信息 | 行业通用配色 |

### 功能色标准

- **成功** - 绿色系（如 #52C41A）
- **警告** - 黄色/橙色系（如 #FAAD14）
- **错误** - 红色系（如 #F5222D）
- **信息** - 蓝色系（如 #1890FF）

### 颜色使用原则

1. 避免页面中出现过多色值导致画面混乱
2. 保持颜色的一致性，相同功能使用相同颜色
3. 考虑无障碍设计，确保足够的对比度

## 字体规范

### 字体选择

- **系统默认字体** - 优先使用，确保用户日常使用顺畅
- **备用字体** - 准备备用字体维护不同平台可读性

### 字号规范

| 场景 | 字号 | 说明 |
|------|------|------|
| 主要文本 | 14px | 默认正文，多数显示器可读性好 |
| 次要文本 | 12px | 辅助信息、时间戳 |
| 标题/重要信息 | 16-18px | 页面标题、模块标题 |
| 大标题 | 20-24px | 一级页面标题 |
| 特殊场景（数据页） | 12px | 中后台数据页面，查看更多数据 |
| 特殊场景（老年用户） | 16-18px | 针对中老年用户群体的软件 |

### 行高规范

- 一般情况下，**行高不小于字号**
- 可根据padding高度给予字体行高，方便开发
- 推荐行高比例：1.4 - 1.6

### 字重规范

- **Regular (400)** - 正文、描述
- **Medium (500)** - 次级标题、强调
- **Bold (600-700)** - 主标题、重要数据

## 图标规范

### 图标类型

1. **线性图标** - 简洁、现代感强，适合轻量级界面
2. **面性图标** - 视觉重量大，适合需要强调的场景

### 设计规范

- **尺寸规范** - 限定基础尺寸（16px, 20px, 24px, 32px）
- **出血位** - 预留安全区域，避免裁切
- **圆角** - 统一圆角大小，保持风格一致
- **描边宽度** - 统一描边粗细（1px, 1.5px, 2px）

### 使用原则

1. 图标语义清晰，易于理解
2. 同一页面保持图标风格统一
3. 图标与文字搭配时保持对齐

## 组件规范

### 基本组件

#### Button 按钮

**样式类型：**
- 主要按钮 - 主色背景，用于主操作
- 次要按钮 - 白色/灰色背景，用于次要操作
- 文字按钮 - 纯文字，用于低优先级操作
- 图标按钮 - 图标为主，用于工具栏

**状态规范：**
- 正常 (Normal)
- 悬停 (Hover)
- 按下 (Active)
- 禁用 (Disabled)
- 加载 (Loading)

**尺寸规范：**
- 大按钮 - 高度48px（用于主要操作）
- 中按钮 - 高度40px（默认尺寸）
- 小按钮 - 高度32px（用于紧凑布局）
- 迷你按钮 - 高度24px（用于标签、徽章）

#### Input 输入框

**状态：**

- 只读

#### Select 选择器

## 文案规范

### 简洁易懂

- 省略反复无用的词汇
- 使用简洁的语句表达
- 避免专业术语，使用用户语言

### 突出重点

- 区分重要与次要信息
- 让用户快速找到所需内容
- 使用视觉层次强化信息层级

### 避免极端表述

- 避免使用"绝不"、"一定"等绝对化词汇
- 使用更温和的表达方式
- 给用户留有余地

### 常用文案规范

| 场景 | 规范示例 |
|------|----------|
| 按钮文案 | 使用动词开头，如"立即购买"、"提交申请" |
| 提示文案 | 说明问题 + 解决方案 |
| 错误文案 | 友好提示 + 操作建议 |
| 空状态 | 解释原因 + 引导操作 |

| 层级 | 名称 | 用途 |
|------|------|------|
| 4 | Popout | 弹出层，弹窗、菜单、Toast |

## 无障碍设计规范

### ARIA属性使用

```html
role="button"           # 定义元素角色
aria-label="描述"       # 元素描述
aria-labelledby="id"    # 关联标题
aria-hidden="true"      # 对读屏软件隐藏
aria-selected="true"    # 选中状态
aria-expanded="false"   # 展开状态
aria-live="polite"      # 动态内容更新
```

### 键盘导航

- 所有可交互元素支持Tab键访问
- Enter/Space键触发按钮
- 方向键在选项中切换
- Esc键关闭弹窗

### 焦点管理

- 弹窗打开时聚焦第一个可交互元素
- 弹窗关闭时焦点返回触发元素
- 焦点可见（清晰的焦点样式）

### 对比度要求

- 正文文字与背景对比度至少 4.5:1
- 大文字（18px+或14px+粗体）对比度至少 3:1
- 图标与背景对比度至少 3:1

## 设计系统建设

### 设计系统的价值

1. **提高效率** - 减少重复设计工作
2. **保证一致性** - 跨页面、跨产品体验统一
3. **降低沟通成本** - 设计师与开发使用同一语言
4. **易于维护** - 集中管理，一处修改全局生效

### 设计系统构成

1. **设计原则** - 指导设计决策的核心价值观
2. **视觉语言** - 颜色、字体、图标、间距
3. **组件库** - 可复用的UI组件
4. **设计模式** - 解决常见问题的最佳实践
5. **设计资源** - Sketch/Figma源文件、图标库

### 实施建议

1. 从业务需求出发，不要过度设计
2. 保持灵活性，允许适当的自定义
3. 建立组件使用文档和示例
4. 定期收集反馈并迭代优化
5. 培养团队使用设计系统的习惯
